The AI coder that shows its work.

cancho-code builds software one small piece at a time, and the compiler — not the model — decides when each piece is done.

Trust the check, not the chat

  
Most assistants say “done” and leave you to read the diff. Here, “done” has to be earned.

  

    
✅
Compiler-verified
Every piece is type-checked by the real compiler and run against its own examples. A model's confidence counts for nothing.

    
🧩
Small pieces
A brief becomes a plan of small units. A failing unit is fixed alone, and everything already verified is re-checked after each step.

    
🛑
Loops that stop
Attempt ceilings and a “same refusal twice” rule end a stuck run, named, instead of burning your money.

    
🔌
Any model
Claude with an API key, or a local model through Ollama. You pick the provider and the model every time.

  






  
How it works

  
Plan, build, check, repeat. Each lap ends in a verdict you can read.

  

  
  






  
One command, one board

  
Give it a brief. It writes the plan, checks it, builds every unit with the compiler as judge, and ends with a verdict.


build/cancho-build "$CANCHO" brief.txt work "$AGENT" \
    --provider anthropic --model claude-haiku-5-5 --guide docs/plan-guide.md --review on

[BUILD_VERDICT]  done

  

    
📝
Your names stay
The functions your brief names are the ones built. A plan that renames one is refused before anything is built.

    
📋
A board, not a transcript
A read-only page shows every unit as waiting, building, verified or stuck, with its attempts, the compiler's refusals, tokens and cost. Open it and load a run's board.json.

    
▶️
Resumes
Killed halfway? The next run keeps the verified units and does not ask for the plan again.

  

  
Example, one run: Claude Haiku 5.5 built the roman library from its brief alone, 6 units, 88 seconds, $0.013, and passed the hidden audit 439/439. One run on one task; the numbers below are the larger measurement. Details: docs/build.md, docs/dashboard.md.

Try it

  
You need the cancho compiler and either an Anthropic key or a local Ollama model.


git clone https://github.com/alpibrusl/cancho-code.git
cd cancho-code
export CANCHO=<path-to-the-cancho-binary>      # the commit named in .cancho-rev
export CANCHO_PACKAGES=<compiler-checkout>/packages

"$CANCHO" build tests/programs/fix.cho \
    src/driver.cho src/checker.cho src/signature.cho \
    src/loop_check.cho src/snapshot.cho src/trail.cho src/acceptance.cho \
    --std --backend cranelift -o ./fix

  
Then fix a broken program with a local model, or build a whole plan with Claude: the step-by-step guide has both.
