# Services (acceptance, hidden attack, demo) and the first Claude builds

## What was built
- `eval/services/{jobs,invoices,webhooks,kvstore}/`: lex-code's four services adapted to cancho (flags instead of environment variables, state in memory, no SQL; the
  loopback-only requirement of the original briefs is dropped because a cancho listener binds the port on all interfaces and has no way to choose the address). Each has a reference application that passes its acceptance
  scenarios and its hidden attack in full (jobs 64/64 and 188/188, invoices 44/44 and 165/165, webhooks 51/51 and 129/129, kvstore 59/59 and 225/225). The authors
  ran 7-10 deliberate mutations of each reference and each was caught by a named attack check; those mutants are not in the repository, only the report.
- `fix` accepts extra files (the skeleton and the http-server package); its acceptance command runs the scenarios; `scripts/test-services.sh` pins the references,
  the stub's failure, a broken project, and the demo.
- `eval/demo.py <service> <project.cho>`: builds, starts, walks a scripted session (curl commands with the real responses), `--keep` leaves it running.

## Claude Haiku 5.5, one run per service, whole service in one file, through the fix loop (6 attempts)
| config | jobs | invoices | webhooks | kvstore |
|---|---|---|---|---|
| default thinking, 16k output bound | no answer (bound hit 3x) | same | same | same |
| default thinking, 48k bound | no answer (hit 2x, 600 s agent timeout) | same | same (3x) | same |
| effort low, 48k, **acceptance exit status fixed** | no answer (thinking used the whole bound, 0 visible characters) | same | **verified, attack 129/129**, 1 call, 43.9k output tokens, $0.023, 174 s | same |
| thinking disabled | wrote a program (5 calls) that does not compile; loop stopped on a repeated refusal | same (3 calls) | not run | same (3 calls) |

Notes: the first effort-low round reported `verified` for two services with a low attack score (32/165, 57/129): the acceptance wrapper's pipe through `tee`
masked the scenarios' exit status. Fixed (the wrapper keeps the output in a file and exits with the scenarios' status); those two results are not valid.
With thinking on, a service-sized task makes the model spend its whole output bound on hidden reasoning (0 visible characters in 48,000 tokens) in three of
four services; with thinking off it writes a program quickly but gets cancho's rules wrong (an effect row that declares `heap` and never uses it, a name not in scope,
a `res` value assigned over), and the loop's stop on two identical refusals ends the run.

## What this says
Acceptance and the attack work as designed (the reference passes, the stub fails, the harness fails when it is made lenient). Building a whole service in one
request is too big for this model at either thinking setting; webhooks, the one that fit, passed every hidden check on the first attempt. The way forward is the
same as for libraries: a breakdown into units whose logic is small and whose acceptance is cheap (the briefs name the pure functions), with the application as the
last unit. That needs unit tests that can be compiled with the skeleton present, which `cancho test` (it supplies its own `main`) does not allow today.
