# The memory: what the evidence is, and an A/B (2026-10-16)

Everything below is measured from run directories (`eval/results/2026-10-16-memory.json` has the numbers, `eval/memory_ab.py` the harness). The question: does `--memory` (docs/memory.md) help the unit agent, with lessons mined from other items' runs only?

## The evidence base

The miner was run over every run directory under `runs/` (142 entries, nested run directories included):

| | |
|---|---|
| runs with a journal (docs/journal.md) | 77 (the 39 runs of this experiment's training and A arms, 38 earlier ones, 8 of them `runs/jr/`) |
| runs read from their trails only (legacy mode: no code, so no fixes) | 3,748 trail files |
| attempts seen | 4,951 |
| refusals (an attempt the compiler or the examples refused) | 957 |
| classes (names, types and numbers taken out) | 75 |
| classes with enough evidence (3 occurrences in 2 runs) | 37 |
| classes with a fix to show (only journals have diffs) | 8; all 8 are also `active` |
| superseded | 0 (no run before this one carried a lesson, so none could be contradicted) |

The journals are the thin part: the 8 early journal runs (`runs/jr/`) hold 55 attempts and **2** refusals; 52 of the 55 attempts verified at once. History is where the evidence is, and history has statistics but not fixes.

The top ten classes (`next` is how often the attempt after the refusal verified):

| 2 | `not-a-function:`N` is not a function in this program` | 154 | 44 | 61 | 12/126 | legacy | 0 |
| 3 | `acceptance:test N ... FAILED` (an example failed) | 135 | 69 | 78 | 21/82 | mixed | 0 |
| 4 | `arity-mismatch:`N` takes # arguments, but # were given` | 49 | 24 | 24 | 24/49 | legacy | 0 |
| 5 | `unknown-name:`N` has no variant `N`` | 32 | 6 | 6 | 1/27 | legacy | 0 |
| 6 | `module-not-imported:`N` is not an imported module here; `N` it to reach its types` | 31 | 29 | 30 | 19/30 | mixed | 3 |
| 7 | `type-mismatch:expected `T`, found `Buffer`` | 30 | 21 | 23 | 6/25 | legacy | 0 |

Three read against the raw evidence:

- **#6, the import** (`L c2bc565d`): the fix the miner kept for it is `+import std.list;`. The raw journal of `mem-t-jsonptr-1`, unit `parse`: attempt 0 was refused (`` `list` is not an imported module here; `import` it to reach its types ``, line 126 of the project), attempt 1's diff blob adds exactly `import std.list;` and verified. The two other kept fixes are the same line from `ae-brief-editdistance-1` and `ae-brief-ini-2`. A sensible lesson.
- **#7, `Buffer` where a slice is wanted** (`L864bef6c`): this is the pitfall that became the AGENTS.md hint, found here without anyone looking: 30 occurrences in 21 runs, and the attempt after it verified in only 6 of 25 cases. The raw `.feedback` of `project-durationplus-3` says `` expected `&?r3 [byte]`, found `Buffer` `` (region numbers are inside the backticks, which is why the class takes types out). It has no fix because every run it comes from predates the journal.
- **#4, arity** (`L060e6230`): 49 occurrences, and an independent count over the raw trail files gives the same 49 in 24 run directories. The trail of `d16-invoices-1`, unit `validate_create`, shows what the class is for: attempts 0, 1 and 2 were refused for `is_object`, `is_string` and `is_int` taking a different number of arguments than the model wrote: **three different signatures, so the same-signature stop rule never fired, one class**. The fourth attempt verified.

What this says about the design: a count and a success rate are worth having already (they rank what to look at, and `--promote` takes the top of the list once a journal repeats it), but a lesson becomes *advice* only when a journal has the fix. Recall injects only those, so with today's journals very little is injected.

## The A/B

13 items (`eval/*/brief.txt`), brief only, `claude-haiku-5-5`, the same primer, `build/cancho-build` at the commit of this branch. Arm A is `--memory`-less; arm B gives each item the memory mined **only from the journals of the other 12 items** (leave-one-item-out: 36 runs, the 13 items x 1 training run (`mem-t`) plus the A runs, minus the item's own; each item's memory has 2 or 3 active lessons, 1 or 2 with a fix, and exactly one that can ever be recalled, the import lesson #6: the other one with a fix is an `acceptance` class, and a lesson is only matched to a refusal of the checker). No facts. 2 runs per item and arm.

| | A, without memory | B, with memory |
|---|---|---|
| runs | 26 | 26 |
| `done` | 22 | 23 |
| fully right (hidden audit: all cases) | 14 | 17 |
| audit cases passed | 4,684 / 5,004 | 4,620 / 5,004 |
| units | 164 | 155 |
| attempts per unit | 1.073 | 1.077 |
| refused attempts | 15 | 14 |
| attempts that carried a lesson | 0 | 4 |
| ... of which the attempt verified | - | 3 |
| model calls | 245 | 241 |
| cost | $0.554 | $0.597 |

Per item (`done units/total, audit passed/of`, two runs each): see the JSON; the rows that differ between the arms are base64 (equal), csv (A: plan_failed, done 35/50; B: stuck 0/50, plan_failed), duration (A: done, stuck 42/64; B: done twice), sortedmap (A: stuck twice; B: done twice, 124/124), roman (A: done twice; B: done, stuck), ini (the audit's 0/76 comes and goes in both arms).

**How often a recalled lesson preceded a verified retry: 3 of 4.** All four were the import lesson (#6), on `csv/format_line`, `editdistance/closest`, `ini/parse` and `jsonptr/format`. The fourth compiled and then failed an example (`acceptance_failed`): the lesson fixed what it was about, the unit had another fault.

**Without the memory the same retry verified 2 of 2.** In arm A the import refusal came twice (`csv/format_line`, `editdistance/closest`) and the next attempt verified both times, with no lesson. The model reads the refusal (`import it`) and does what it says. Of the 11 refusals in A that were followed by another attempt, 2 were of a class the memory knows; of 12 in B, 4. The memory's reach on this base is 4 prompts in 26 runs.

### What this does and does not show

- **Nothing about whether the memory helps.** 2 runs per cell is noise: the same item twice gives `plan_failed` and `done 35/50` (csv, A), `done` and `stuck` (duration, A), `done` and `stuck` (roman, B). The net +3 fully-right runs in B is sortedmap +2, duration +1, ini +1, glob +1, expr -1, roman -1; no run that gained carried a lesson (the four that did are csv-1, editdistance-2, ini-2 and jsonptr-1), so none of the gain is the memory's. The difference in `done` (22 against 23) is one run.
- **What it does show** is the plumbing, end to end on the real API: lessons mined from journals, recalled by class, the block in the prompt blob, the ids and texts in the journal's `memory` field, a run that is otherwise the same. The recalled retry verified in 3 of 4, against 2 of 2 without it and 19 of 30 in the mining base: consistent with "no difference", and with "a little help"; the numbers cannot tell them apart.
- **Why the effect is small here, and probably in general for this model and primer:** the refusals that recur in the mined base are the ones a model with the language page fixes by reading the message (an import, an unknown name). The recurring pitfalls it does *not* fix at once (#2, #4, #5, #7, #8: next attempt verified 9% to 25% of the time) are exactly the ones with no fix in the memory, because they come from runs before the journal. The way forward is more journals, then `--promote` (upstream, into AGENTS.md, which is where the `Buffer` hint went) rather than per-run injection, which for these classes would have only the journals of this experiment to quote.
- A run is explainable and reproducible either way: the prompt blob and the `memory` field say what the model saw.

### Cost

$1.51 in all: smoke run $0.017, the training arm $0.343, A $0.554, B $0.597. The budget was about $1.50.

### Reproduce

```sh
CANCHO=... python3 eval/memory_ab.py run mem-t 1 $OUT/t --primer primer.md      # training: one run per item
CANCHO=... python3 eval/memory_ab.py run mem-a 2 $OUT/a --primer primer.md      # arm A
python3 eval/memory_ab.py mine $OUT/mem $OUT/t $OUT/a                            # <item>/lessons.jsonl from the other items' journals only
CANCHO=... python3 eval/memory_ab.py run mem-b 2 $OUT/b --memory-root $OUT/mem --primer primer.md   # arm B
python3 eval/memory_ab.py report $OUT mem-a mem-b 2026-10-16-memory --memory-root $OUT/mem --lessons <lessons.jsonl of the whole base>
```
