# Edit mode: the model returns the unit, a program splices it in (`--output patch`)

The measured waste (2026-10-17, `thinking tokens`): for every unit the model re-emitted the whole project file. In patch mode it is asked for only the code to add or change and `src/splice.cho`
puts it in (an item with the same name is replaced in place, a new one is appended, imports are deduplicated). Same experiment as the baseline: the 13 hand-planned items, 3 runs each, Claude Haiku 5.5,
same plans, primer and hidden audits. Raw data: `2026-10-17-edit-mode.json`.

| | builds `done` | audit points | output tokens | cost |
|---|---|---|---|---|
| whole file (baseline) | 38/39 | 7505/7581 | 633,849 | $0.372 |
| **patch** | **38/39** | 7478/7581 | **469,146 (-26%)** | **$0.298 (-20%)** |

Quality held: the same 38 of 39 (the failure is again `ini` run 1), 27 audit points fewer, all from one `base64` run that finished with a 960/987 score. Output tokens fell on every item
(from -4% on `tokenbucket` to -36% on `editdistance` and `csv`); `basics` and `tokenbucket` hardly move because their units are small and the thinking dominates.

**What is left is thinking.** In patch mode 82% of the output tokens are thinking (382,466 of 469,146; it was 56% when the visible part was a whole file). The visible tokens are now almost entirely the unit
itself: efficiency over visible tokens 0.90. The next lever is therefore not the answer but how much the model deliberates per unit (effort per unit, or none for a unit whose description already fixes the algorithm).

Note on the metric: in patch mode `program_chars` is the patch, so the "growth of the file" definition of the mandatory share does not apply; `metrics.py` takes the share as 1.0 when the run was a patch run
(`run.json` has `"patch": true`; gate in `scripts/test-metrics.sh`). Efficiency numbers of the two modes are therefore not comparable; compare output tokens and cost.

Caveats: 3 runs per item, one model, plans written by hand; the splice rules (identity by name, in-place replacement) assume the model returns complete items.
